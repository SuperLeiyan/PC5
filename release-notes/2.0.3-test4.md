**Test build: 2.0.3-test3 with three more fixes from your reports.** Includes everything in 2.0.3-test, test2 and test3. Publish as a pre-release.

### Install

Copy the `PPSA11018` folder from `PPSA11018.zip` over your PC5 folder. Games, saves and settings stay.

**Going back:** games installed with 2.0.3-test2 or newer need one of these builds (or newer). On 2.0.2 or 2.0.3-test, install them again. Older games are fine either way.

### New since 2.0.3-test3

- **Install on a USB drive** (replaces Play from USB): with a USB drive plugged in, PC5 asks where a game goes, **Console** or **USB drive**. On the drive it goes in its `PC5` folder and plays from there; its saves stay on the console. Uninstalling deletes it from the drive too.
- **An INSTALL folder on each USB drive**: `PC5/INSTALL`. Games put there are offered as those in PC5's own INSTALL folder are, when PC5 opens or when the drive is plugged in. Installed on that same drive, a game is moved at once.
- Games set to play from a USB drive with an earlier PC5 keep working.

### Fixed since 2.0.3-test3

- **"Too many open files"**: games that keep many files open (an Unreal Engine game's archives, an older game's packages) could run out of what the console allows a program, and stop or fail to load the next level. PC5 now asks the console for all it allows, and its log says how many that is.
- **.NET parts of a native game**: a game that loads a .NET library beside its program (an Unreal Engine game's speech) now gets the .NET runtime, as a .NET program does.
- **Games that read the network adapter's address**: the console had no adapter to show besides the internal one, so a game that asks for its adapter's address without checking the answer could crash a few seconds in. PC5 now shows an unplugged wired adapter, as a PC whose network cable is out has: such games see themselves offline instead.
